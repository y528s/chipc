City & Hackney IPC Portal — rebuild plan on a page

A new model: the GP section and the IPC area consolidate into one portal. What we're changing, what stays the same, and how we get from this prototype to the live site — for sign-off.

The goal — a new model

The separate IPC area goes away. The GP section and the IPC portal consolidate into one portal — one site, one navigation, one login, one search, one back end — in the approved design (Design 1 — The IPC Hub). Access is controlled per item, not per area: anything for member practices simply carries a padlock 🔒 wherever it appears. Every page is editable by IPC admins directly on the page — no developer needed for day-to-day content changes.

What changes / what stays

Changes

  • The IPC area disappears as a place. One consolidated portal — the familiar IPC / General Practice split survives only as two menu groups in the header, purely for wayfinding. Pages, search, the document library and the back end are all shared.
  • Access is per item, not per area — anything for member practices carries a 🔒 everywhere it appears (navigation, search results, listings). Members see everything seamlessly; anyone else is asked to sign in only when they open a locked item.
  • No standalone document library — documents live where they belong (inside contracts, pathways, policies and services, e.g. a document page with preview) and are all reachable through the one portal search. They're still managed centrally in the back end.
  • Front-end editing — admins toggle "edit" on any page and change text in place (try the ✎ Admin: edit this page button on the prototype).
  • One consolidated back end — a single admin area for the whole portal; a tick-box marks any page or document as member-only and the padlock appears automatically.

Stays the same

  • Bulletins do not change — content, format and the weekly publishing workflow stay exactly as they are today; only the portal navigation around them is new.
  • All existing content — documents, contracts, policies migrate over; nothing is lost.
  • Logins — members keep their existing accounts; open clinical content needs no login at all.
  • The approved GP-section design — the whole hub now uses it.

In the header these group into two menus — General Practice (Pathways · Services · Topics) and 🔒 IPC (Bulletins · Contracts · Policies · Staff Bank) — but that structure exists only in the menu; everything else is one consolidated portal. There is no separate Documents section: documents sit inside their sections and in search.

How the merged back end will work (WordPress)

  • One WordPress install for the whole hub — no more separate GP-section and portal back ends to keep in sync.
  • The site is rebuilt as a WordPress theme matching this prototype exactly — each block here maps to an editable block in WordPress.
  • Admins edit the front page (and every page) in place; editors see the page exactly as members do.
  • Pathways, services, documents, contracts and policies become structured content types — upload a file, pick the topic/contract, tick "members only" if it is, and every listing, search result, padlock and "recently updated" panel updates itself.
  • One consolidated IPC dashboard: bulletins, documents, contracts, policies, pathways, events and news in a single menu, with clear roles for who can edit what (clinical editors, contracts team, comms, admins).

Getting to live

  1. Now — review this prototype. Click through every page, try the admin edit button, and confirm the design and structure.
  2. Sign-off. Stakeholders approve the design and the plan on this page.
  3. Build on staging. WordPress theme + content types built to match the prototype on a private staging server; existing content migrated across.
  4. Test. Admins test editing; a small member group tests finding documents. Fixes applied on staging.
  5. Go live. Staging is pushed to the live server in one switchover; the old site is kept as a rollback for 30 days.

The ask

Approve the design and this plan so the staging build can start. Feedback on any page of the prototype is welcome before sign-off — everything you see is still easy to change.
